## 3. 模块边界（避免互相改坏）

| 层 | 输入 | 输出 | 不允许做的事 |
|---|---|---|---|
| `imu_mpu6500` | SPI | `ImuSample` | 不做滤波、不做姿态 |
| `attitude` | `ImuSample` | `Attitude` | 不做控制、不读遥控 |
| `control` | `Attitude` + `RcCmd` | `CtrlOut`（幅度/偏置/差动/相位/频率） | 不直接写舵机 |
| `mixer` | `CtrlOut` + 相位 | `ServoCmd`（舵机角） | 不做 PID |
| `servo_out` | `ServoCmd` | LEDC 脉冲（**反相**） | 不做混控/逆解 |
| `rc_espnow` | 无线帧 | `rc_frame_t` | 不做限幅/状态判断 |
| `telemetry` | 状态 | 遥测帧 | 不做控制 |
| `safety` | 全部状态 | 允许/禁止、限幅后的 `RcCmd` | 不直接写硬件 |

## 4. 协作守则（照着做，能省掉 90% 冲突）

1. **参数只改 `config.h`**：引脚、频率、限幅、增益都集中在那里；改引脚必须同步 `docs/00`。
2. **`shared/protocol.h` 改动 = 协议变更**：必须两固件同步 + 升 `PROTO_VER` + 在本文档记一笔。
3. **文件归属**：每个 `.h/.cpp` 顶部写 `负责人：`；别人只读不改，需要改就在群里说。
4. **分支**：`main` 保持可编译；每人一条 `feat/<模块名>` 分支，合并前跑 `tools/host_test`。
5. **提交信息**：`feat(mixer): 加入相位发生器` / `fix(servo): 修正反相占空比`。
6. **单元测试**：纯算法/协议先在 `tools/host_test` 里验证，再上台架。
7. **不要提交**：`.pio/`、编译产物、日志、大二进制（STL 放网盘，仓库只留说明）。

**方式一（推荐，快）**：把整个 `项目计划/` 文件夹打成 zip 发群/网盘：

```powershell
Compress-Archive -Path "D:\git stor\项目计划" `
    -DestinationPath "D:\git stor\项目计划_share_$(Get-Date -Format yyyy-MM-dd).zip"
```

**方式二（长期协作）**：`git init` 后推到内网/GitHub 私有仓库，按第 4 节分支约定开发。
